## 背景

Phase 0 将首页定义为最新内容入口，并设置独立的“全部文章”页；同时明确 v1 不做站内搜索。Phase 2 低保真梳理时，用户确认早期个人博客不需要把最新内容与完整内容拆成两条浏览路径，希望在首页个人介绍区下方直接浏览、分类和搜索全部内容。

该变化减少一个主要路由和一次导航跳转，但也使首页同时承担个人入口与内容发现职责，因此需要控制个人区、筛选区和内容列表的视觉层级，并明确未来内容量增长时的重新评估条件。

## 已批准决策

### 首页与内容发现

- 不再建设独立的“全部文章”页面。
- 首页顶部保留个人资料区，下方展示全部已发布内容。
- PC 首页个人资料区拥有明显大于单条内容的视觉体量，约占普通桌面首屏的 `35%–45%`，但不使用全屏 Hero。
- 首页提供“全部”“文章”“学习笔记”“工具分享”四个分类按钮。
- 首页提供轻量多字段搜索，匹配标题、摘要、分类和标签。
- 搜索忽略大小写和首尾空格，不支持错别字纠正、拼写相似度或相关度评分。
- 分类与搜索可以叠加；结果继续按发布日期倒序排列。
- v1 不提供分页、加载更多或用户可配置排序。
- 标签显示在内容元数据中并参与搜索，但不提供独立标签筛选器。
- 首页内容过长只有在真实内容规模造成可用性问题后，才通过新 REQ 评估分页或归档。

### 导航与返回路径

- 全站主导航为：首页、实验室、关于我。
- 站点名称继续链接首页。
- 内容详情的返回入口指向首页内容区。
- 404 的恢复入口指向首页或首页内容区。
- 首页内容区使用稳定锚点，供站内返回路径定位；具体路由实现由后续 DEV 定义。

### 视觉方向

- 主视觉为“安静的编辑阅读感 + 轻量代码气质”。
- 基础色为暖纸白背景、炭黑正文和低饱和墨蓝强调色。
- “全部”使用中性墨色，“文章”使用低饱和墨蓝，“学习笔记”使用低饱和琥珀色，“工具分享”使用低饱和青绿色。
- 分类色只用于按钮、徽标和小面积状态，不扩展为大面积页面背景。
- 分类和选中状态同时使用文字、边框或形状变化，不能只用颜色表达。
- 全站只使用系统中文无衬线字体栈和系统等宽字体栈，不引入外链或自托管字体。
- 首页与列表使用较宽容器，内容详情使用窄阅读栏。
- 动效只服务悬停、焦点、筛选和状态反馈，时长范围为 `120–240ms`；不使用视差、持续背景动效或强滚动绑定。
- 所有动效必须支持 `prefers-reduced-motion`。

### 页面信息结构

- 共享框架使用非悬浮导航；PC 为品牌左、导航右，手机为品牌和导航两行。手机不使用汉堡菜单。
- 首页由较大的个人资料区、搜索与分类区、全部内容列表、关于我和实验室入口组成。
- 内容详情由返回入口、标题与元数据、可选封面、窄正文、图片、代码块和文章目录组成。PC 目录位于右侧，手机目录默认收起。
- 关于我由完整个人介绍、当前学习方向、技能方向和外部联系方式组成；不使用履历时间线、技能百分比或站内联系表单。
- 实验室 v1 直接展示一个可操作实验，不提前建设实验目录；实验必须支持键盘、触控和减少动效。

## 未选方案与原因

| 方案 | 未选原因 |
| --- | --- |
| 保留首页最新内容和独立全部文章页 | 早期内容规模不足以支撑两条内容浏览路径，增加一次无必要跳转。 |
| 真正的模糊匹配与相关度排序 | 需要额外算法、依赖和评分规则，对 v1 小规模本地内容收益不足。 |
| 首页只提供标题搜索 | 无法利用摘要、分类和标签，内容发现能力过弱。 |
| 自托管中文字体 | 字体体积、子集化、许可和维护成本不符合 v1 目标。 |
| 高对比或赛博视觉 | 容易压过长文阅读，并与安静编辑感冲突。 |
| 汉堡菜单 | v1 只有三个主入口，没有隐藏导航的必要。 |
| v1 建设实验目录 | 当前只要求一个实验，提前抽象没有实际消费者。 |

## 验证证据

- 用户于 2026-07-24 明确提出取消独立全部文章页，将分类和轻量搜索整合到首页。
- 用户选择轻量多字段包含匹配，不选择错别字容忍或相关度排序。
- 用户逐项确认主视觉、系统字体、暖纸白与墨蓝基础色、分类色、分层宽度和克制动效。
- 用户逐项确认共享框架、首页、详情、关于我和实验室的 PC 与手机低保真结构。
