## 产品定位

Eelex Blog 是一个以学习 Web 开发与前端设计为主要目标，用于发布学习思考、分享工具、展示前端设计能力和个人资料的个人博客与在线简历。

> A personal hub for code, design, and learning.

## 项目目标

### 主要目标

- 完整经历个人 Web 项目从需求、设计、实现、测试、部署到复盘的流程。
- 通过真实博客沉淀前端 UI、交互、动效、样式和设计规范。
- 持续发布学习思考、前端实践和工具分享。
- 用博客本身展示个人资料和前端设计能力。

### 非目标

- v1 不以盈利、社区增长或多人协作为目标。
- v1 不建设完整招聘简历、作品集平台或内容管理产品。
- v1 不为尚未出现的复杂需求提前建设后端和数据系统。

## 目标访客

- 希望了解 Eelex 个人资料、学习方向和前端能力的访客。
- 对 Eelex 发布的学习思考、前端实践和工具分享感兴趣的读者。
- 访问地域兼顾中国大陆与海外。
- v1 界面和内容仅提供中文，不建设多语言系统。

## 内容范围

v1 包含文章、学习笔记和工具分享。三类内容共用统一详情页和统一 MDX 内容结构，通过分类或标签区分，不建设独立工具目录或平行内容系统。

每篇内容至少包含：

- `slug`
- 标题
- 摘要
- 发布日期
- 分类
- 标签
- 正文
- 可选封面

正文支持图片、代码块和文章目录。

## 页面需求

### v1.1 体验扩展

- 全站采用知识库式共享导航、卡片和响应式页面壳。
- 首页桌面采用个人发现侧栏、单列封面文章流和站点统计三栏结构；移动端保持单列。
- 新增归档页、完整搜索结果页、RSS、主题/背景设置、复制链接、阅读时间和上一篇/下一篇。
- 保留文章发布日期，但不提供日历、日期日历标记或日历跳转。
- 项目/产品链接可以公开展示；反馈仅使用邮箱或公开联系方式。
- 商业合作正文模块与商店入口只作为未来扩展，不在当前版本渲染。

### 首页

- 顶部以欢迎标题和简短介绍呈现个人阅读区；首页与关于页的标题和简介使用一致的层级。
- PC 顶部个人区具有明显大于单条内容的视觉体量，但不使用全屏 Hero；标题和简介置于半透明玻璃卡片中，手机端保持紧凑单列。
- 主体展示全部已发布内容，默认按发布日期倒序排列。
- 提供“全部”“文章”“学习笔记”“工具分享”分类选择。
- 提供对标题、摘要、分类和标签的轻量包含匹配；搜索忽略大小写和首尾空格，不提供错别字纠正或相关度评分。
- 分类和搜索条件可以叠加，并显示当前结果数量和明确的无结果状态。
- 内容卡片展示标题、摘要、发布日期、分类或标签。
- 封面可选；没有封面时使用完整纯文本布局，不显示空白占位图。
- 提供进入关于我的明确入口；不提供实验室入口。
- v1 不提供分页、加载更多或用户可配置排序。

### 内容详情

- 展示标题、发布日期、分类或标签和正文。
- 正确渲染图片、代码块和文章目录。
- 提供返回首页内容区的明确入口。
- v1 不提供预计阅读时间、复制链接、上一篇或下一篇。

### 关于我

- 展示姓名或昵称、头像、个人定位和自我介绍。
- 展示技能方向和当前学习方向。
- 提供邮箱、GitHub 或其他已配置的外部联系方式。
- v1 不要求教育经历、工作经历或简历时间线。

### 实验室（已取消）

实验室曾作为与博客核心内容区分的独立探索页规划。2026-07-25 经 `BIZ-20260725-03` 决定，不再纳入 v1；导航、首页入口、`/lab` 和阅读密度交互均不保留。博客核心阅读链路不依赖该模块。

### 404

- 无效地址显示明确提示。
- 提供返回首页或首页内容区的入口。

## 全站导航栏

- 所有主要页面使用统一导航栏。
- 包含：内容、关于我。
- `Eelex Blog` 名称可点击返回首页。
- 当前页面状态清晰可辨。
- PC 与手机端均可正常使用。
- 支持键盘操作，链接无失效或错误跳转。

## 全站页脚

- 所有主要页面使用统一页脚。
- 展示 `Eelex Blog` 名称及版权信息。
- 提供邮箱、GitHub 或其他已配置的外部联系入口。
- 外部链接有清晰名称并能正常打开。
- PC 与手机端布局完整，不遮挡正文。

## 核心访问路径

```text
进入首页
→ 浏览、分类或搜索全部内容
→ 打开详情并阅读
→ 查看关于我或继续浏览其他内容
```

## 内容发布方式

- 内容存放在项目内的本地 MDX 文件中。
- 新增或修改内容通过 Git 提交进入发布流程。
- 推送至远程仓库后由 Netlify 自动构建和部署。
- v1 不使用数据库、在线内容后台或第三方内容同步。

## 基础网站能力

- PC 与手机响应式布局。
- 单一视觉主题，不提供深色模式。
- 基础 SEO，包括准确的页面标题、页面简介、语义化标题层级、`sitemap` 和 `robots.txt`。
- Git 推送后自动部署。
- 使用 Netlify 平台子域名完成首次公开上线。
- 独立域名不是 v1 完成门槛。
- 使用 Netlify 提供的基础用量和短期流量数据，不接入第三方统计脚本。
- 避免依赖可能在部分访问地区不可用的外链字体和公共 CDN 脚本。
- 部署阶段必须实际验证中国大陆与海外的可访问性，不预设 Netlify 在所有地区表现一致。

## v1 明确不做

- 用户注册、登录和个人账户
- 评论、点赞、收藏及社区功能
- RSS、邮件订阅及其他用户订阅功能
- 错别字纠正、相似度评分或全文搜索引擎
- 分页、加载更多和用户可配置排序
- 在线内容后台、数据库和自建后端
- 独立项目或作品页面
- 中英双语或其他多语言系统
- 深色模式
- 站内联系表单
- 完整简历经历和时间线
- 独立域名强制要求
- 预计阅读时间、复制链接、上一篇或下一篇

上述列表是 v1.0 的历史边界。v1.1 由 `REQ-20260820-01` 明确启用归档、静态搜索结果、RSS、主题设置、预计阅读时间、复制链接和上一篇/下一篇；评论、联系表单、CMS、数据库、在线上传后台和日历仍不实施。

范围外功能只能记录为后续 REQ，不得在 v1 实施过程中顺手加入。

## v1 完成标准

- 首页、内容详情、关于我和 404 页面均可访问；实验室不存在且不影响核心阅读链路。
- 全站导航栏和页脚满足各自验收要求。
- 核心访问路径可以完整走通。
- 首页分类筛选和轻量多字段搜索可用。
- 至少发布一篇真实内容。
- PC 和手机端可以正常浏览。
- 图片、代码块和文章目录可以正常显示。
- 基础 SEO、`sitemap` 和 `robots.txt` 可验证。
- Git 推送后能够自动部署到 Netlify。
- 正式 Netlify 地址可以公开访问。
- Netlify 基础用量与短期流量数据可以查看。
- 删除实验室模块不会影响博客核心功能。
- 项目文档、实际页面和验收证据一致。

## GitHub 项目首页要求

Phase 0 的根目录 README 先准确呈现项目目标、范围、状态和文档入口。Phase 7 交付前必须基于真实成品重新设计 GitHub 项目首页，包括：

- 清晰的项目标题和价值说明
- 与最终品牌一致的视觉头部
- 真实页面截图或演示素材
- 准确的技术栈和功能说明
- 可访问的在线地址
- 清晰的本地运行和部署说明

不得使用虚假徽章、虚假演示地址、占位截图或与最终产品不一致的宣传内容。
