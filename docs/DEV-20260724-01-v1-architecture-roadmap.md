## 技术方向

- Framework：Next.js
- Language：TypeScript
- Styling：Tailwind CSS
- Content：MDX
- Hosting：Netlify
- Data source：项目内本地内容文件

具体版本、包管理器、Lint、格式化和测试工具在 Phase 1 开始前结合官方兼容性与 Netlify 支持情况核验。Phase 0 不锁定未经验证的版本和命令。

## 架构原则

- v1 采用静态内容优先架构，不引入数据库、自建后端或登录系统。
- 内容结构与页面展示分离，MDX 元数据是列表和详情的共同来源。
- 页面按用户闭环拆分，不按“先做完整前端层、再做内容层”的方式铺开半成品。
- 共享布局只负责全站导航、页脚和页面容器。
- 实验室作为独立功能边界，不被核心内容模块依赖。
- 外部资源不是关键页面正常显示的单点依赖。
- 公开页面的内容和文案只服务最终访客。

## 模块边界

| 模块 | 职责 | 依赖 | 不负责 |
| --- | --- | --- | --- |
| 全局布局 | 导航栏、页脚、页面容器和当前页面状态 | 路由与站点元数据 | 内容查询和实验逻辑 |
| 个人资料 | 首页摘要与关于我完整资料 | 本地个人资料数据 | 文章渲染 |
| 内容模型 | 定义统一元数据和 MDX 内容入口 | 本地 MDX 文件 | 页面视觉布局 |
| 内容浏览 | 首页最新内容、全部文章、分类和标签筛选 | 内容模型 | 正文渲染 |
| 内容阅读 | 标题、元数据、正文、图片、代码块和目录 | 内容模型 | 列表筛选 |
| 实验室 | 独立展示 UI 或动效实验 | 共享布局 | 被核心内容模块依赖 |
| 网站基础 | SEO 元数据、sitemap、robots 和 404 | 页面与内容元数据 | 内容创作 |
| 部署与统计 | Netlify 构建、部署和基础用量观察 | Git 仓库和构建产物 | 产品数据分析平台 |

## 内容数据流

```text
本地 MDX
→ 读取并校验元数据
→ 生成统一内容集合
├→ 首页最新内容
├→ 全部文章与筛选
├→ 内容详情与文章目录
└→ SEO、sitemap
```

前端不得为首页、列表和详情分别手写三套文章数据。

## 实验室隔离

- 实验室拥有独立路由和模块入口。
- 实验内容不得进入文章集合或个人资料数据。
- 核心页面不得导入具体实验实现。
- 导航栏只通过一个独立入口连接实验室。
- 删除实验室时，允许移除实验路由、模块和导航入口，不应修改内容模型和核心页面。

## 错误与降级方向

- 无效内容地址进入 404，不显示未处理异常。
- 缺少可选封面时使用纯文本卡片。
- MDX 必要元数据缺失时构建失败并给出明确错误，不静默发布不完整内容。
- 外部联系链接缺失时不渲染空入口。
- 外部资源加载失败时不影响正文阅读。
- Netlify 构建失败时保留上一个成功部署版本，并通过部署日志定位原因。

## 验证方向

- 内容模型和元数据校验
- 首页、列表、筛选和详情的核心路径
- 图片、代码块和文章目录渲染
- 导航栏、页脚和 404
- 实验室删除后的核心页面回归
- PC 与手机响应式
- 键盘导航和基础可访问性
- SEO 元数据、sitemap 和 robots
- 生产构建与 Netlify 自动部署
- 中国大陆与海外的人工访问检查

## 分阶段计划

### Phase 0：文档体系与范围基线

目标：

- 建立 Agent 规则、产品基线、文档治理、决策记录、技术方向和进度记录。

DoD：

- Phase 0 REQ 的全部验收标准满足。
- 文档之间的引用和状态一致。
- 未创建任何应用代码、依赖或工程配置。

### Phase 1：Git 与工程基础

目标：

- 初始化 Git 和远程仓库。
- 创建 Next.js、TypeScript、Tailwind CSS 和 MDX 工程基础。
- 建立经过验证的开发、检查、测试和构建命令。

DoD：

- `main` 分支可用，忽略规则正确。
- 项目可以在本地启动。
- 类型检查、Lint、测试入口和生产构建命令可执行。
- 依赖版本、目录结构和命令同步到 DEV 与 README。

### Phase 2：设计基础

目标：

- 确定主要视觉方向、阅读原则和 UI/动效原则。
- 建立基础设计 token 和关键页面低保真结构。

DoD：

- 首页、全部文章、内容详情、关于我和实验室的低保真结构获确认。
- 字体、颜色、间距、圆角、页面宽度和动效原则形成文档。
- PC 与手机的信息层级明确。

### Phase 3：页面骨架与模拟内容

目标：

- 建立所有 v1 路由、共享导航、页脚和页面空壳。
- 使用统一模拟内容走通浏览和阅读路径。

DoD：

- 所有 v1 页面可以打开。
- 导航栏和页脚在 PC、手机端可用。
- 首页、全部文章和详情使用同一模拟内容集合。
- 核心访问路径完整走通。

### Phase 4：MDX 与核心阅读链路

目标：

- 接入真实 MDX 内容系统和统一元数据。
- 完成列表、筛选、详情、图片、代码块和文章目录。

DoD：

- 至少一篇真实内容可以发布。
- 首页、全部文章和详情从真实内容集合生成。
- 分类或标签筛选可用。
- 必要元数据缺失时构建给出明确失败。

### Phase 5：关于我、实验室与响应式体验

目标：

- 完成个人资料展示和至少一个可操作实验。
- 完成关键页面响应式和基础交互体验。

DoD：

- 关于我信息结构满足 PRD。
- 实验室至少有一个可操作实验。
- 删除实验室模块后，核心阅读链路回归通过。
- PC 与手机端主要页面可正常使用。

### Phase 6：SEO、可访问性与质量验证

目标：

- 完成基础 SEO、404、键盘操作、体验打磨和核心测试。

DoD：

- 页面标题、简介、语义层级、sitemap 和 robots 可验证。
- 404、空内容、无效地址、图片异常和刷新路径已检查。
- 核心自动检查与人工检查通过。
- 文档与实际实现一致。

### Phase 7：部署、展示与复盘

目标：

- 完成 Netlify 自动部署、公开访问验证、GitHub 项目首页展示和项目复盘。

DoD：

- Git 推送能够触发成功部署。
- 正式 Netlify 地址可访问。
- Netlify 基础用量和短期流量数据可查看。
- 已检查中国大陆与海外的实际访问情况并记录结果。
- GitHub README 使用真实截图、在线地址和准确说明完成展示设计。
- 部署文档和项目复盘文档完成。
- PRD 中全部 v1 完成标准逐项通过。

## Phase 2 路线修订（2026-07-24）

关联需求：[`REQ-20260724-04-phase-2-design-foundation.md`](REQ-20260724-04-phase-2-design-foundation.md)。关联决策：[`BIZ-20260724-02-phase-2-product-design-decisions.md`](BIZ-20260724-02-phase-2-product-design-decisions.md)。

以下内容局部替代本文中与独立“全部文章”页和“v1 不提供搜索”冲突的旧路线；其他架构原则、模块隔离和 Phase 顺序继续有效：

- 内容浏览模块仍消费统一内容集合，但其 v1 页面入口改为首页内容区，不再拥有独立“全部文章”路由。
- 首页同时承担全部内容列表、分类选择、轻量多字段搜索和无结果状态。
- 搜索只执行标题、摘要、分类和标签的规范化包含匹配，不引入搜索服务、模糊评分或新数据源。
- 共享导航的 v1 入口改为：首页、实验室、关于我。
- 内容详情和 404 的内容恢复路径指向首页内容区。

阶段 DoD 修订：

- Phase 2：确认共享框架、首页、内容详情、关于我和实验室的 PC/手机低保真结构；建立基础设计 token。独立“全部文章”页不再是 DoD。
- Phase 3：建立当前 PRD 中的全部 v1 路由和页面骨架；首页骨架包含个人区与内容发现区，但仍只使用统一模拟内容。
- Phase 4：接入真实 MDX 和统一元数据；在首页实现完整内容集合、分类选择、轻量搜索、结果数量、无结果状态和详情阅读链路。
- Phase 5～7：实验室隔离、质量验证和部署顺序不变。

原文中的旧阶段描述作为历史记录保留，不应再被后续 REQ 或实施计划用作独立“全部文章”页的依据。
