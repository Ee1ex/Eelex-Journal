## 目标

使用统一、可公开的个人资料完成“关于我”展示；交付一个与博客核心阅读链路隔离的阅读密度实验；验证关键页面在桌面、平板和手机上的响应式与基础交互体验。

## 已确认输入

- 公开昵称沿用现有 `Eelex`，定位、介绍、学习方向和技能方向沿用当前项目内资料，实施前可以由用户更新为新的公开文案。
- 未提供可公开使用的个人图片，因此本期头像采用不依赖外部资源的字母头像；不创建或下载人物图片。
- 已知公开 GitHub 主页为 `https://github.com/Ee1ex`，作为本期唯一外部联系方式；未提供邮箱，不渲染邮箱入口。
- 实验采用“阅读密度实验”，提供“紧凑”“舒适”“宽松”三种预览状态和重置操作。
- 实验状态仅保存在当前页面内存中；不写入 URL、`localStorage` 或其他持久化存储，刷新后恢复默认状态。
- 响应式验收视口为 `320px`、`375px`、`768px` 和 `1280px`；移动端继续保留全部三项主导航，不使用汉堡菜单。

## 范围

- 建立唯一公开个人资料来源，供首页摘要、关于页和页脚消费。
- 关于页展示字母头像、完整介绍、学习方向、技能方向和实际配置的 GitHub 联系方式。
- 实验室展示一个可操作的阅读密度实验、操作说明、三种状态和重置入口。
- 实验必须可使用键盘和触控完成操作，不依赖悬停；在 `prefers-reduced-motion: reduce` 下不产生非必要动效。
- 验证首页、内容详情、关于我、实验室、导航与页脚在约定视口下没有横向溢出，且焦点与操作路径可用。
- 验证实验室不导入内容仓库，核心阅读页面不导入实验实现；移除实验室路由、模块和导航入口后，核心阅读链路的现有测试仍应通过。

## 非目标

- 不修改 MDX 内容模型、内容搜索、分类、详情目录、静态路由、滚动重置或 Phase 4 的无 URL 搜索状态。
- 不增加实验目录、实验分享链接、持久化偏好、后端、CMS、SEO、部署、远程 CI、完整履历、技能百分比或站内联系表单。
- 不替换 Phase 2 已批准的设计 token、字体策略或全局减少动效规则。
- 不新增第三方运行时依赖、外链字体、外部图片或公共 CDN 脚本。

## 验收标准

- 首页摘要、关于页与页脚从同一公开个人资料来源读取；关于页显示字母头像、介绍、学习方向、技能方向和 GitHub 入口，不显示空联系方式。
- 阅读密度实验使用语义化、可聚焦的原生控件完成三种状态切换；鼠标、触控和键盘均可完成切换，重置后回到“舒适”状态。
- 减少动效偏好下，实验状态切换不使用额外动画或持续过渡。
- `320px`、`375px`、`768px` 和 `1280px` 下，约定页面和导航无水平滚动，内容阅读、外链与实验控件可操作，键盘焦点始终可见。
- 实验室代码不导入 `src/content/*`；首页、内容详情、关于页和共享布局不导入具体实验实现。
- 新增资料与实验的定向测试通过；`corepack pnpm format:check`、`typecheck`、`lint`、`test`、`build`、`check` 和 `git diff --check` 通过。
- 完成桌面、平板、手机和键盘人工检查，并在 REQ、PROG、PRD、文档索引与实施计划中记录证据。

## 依赖与边界

- 依赖已完成的 Phase 2 视觉 token、Phase 3 页面壳和 Phase 4 内容阅读链路。
- 实验室只通过独立路由和主导航连接到网站；它不是内容模型、个人资料或阅读路由的依赖。
- 本期仅使用现有 GitHub 联系方式；后续新增邮箱或其他外部链接需更新公开资料来源和测试。

## 风险

- 字母头像只能表达品牌昵称，不能替代用户未来希望展示的真实个人照片；如提供可公开使用的图片，应通过新 REQ 或本 REQ 的批准后补充记录改变资源策略。
- Vitest 当前使用 Node 环境，客户端状态交互需要通过纯状态逻辑单元测试和人工浏览器检查共同验证。
- 响应式体验依赖真实浏览器视口检查；自动测试不能独立证明触控布局和焦点可见性。
